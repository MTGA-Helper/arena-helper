Pure logic lives in `renderer/decksLogic.js`, exercised by the smoke test against the real payloads.

## 2026-10-26 — Phase 0 engine fixes: collection stats rarity fan-out + B3 next-action bridge transplant (TURBO surge Day 1)

- **What:** Two production-engine fixes, landed on dev. (1) `/collection/stats` (`apps/api/collection.py`): the rarity counts joined `UserCollection` straight to `CardPrint` on `card_id`, so every owned copy was summed once per print of that card. The query now counts through one canonical print per card (earliest print), so each owned card counts exactly once. (2) B3 next-action bridge (`apps/api/services/next_action_service.py`): the Oct 16 bridge repair (commit 0bac155) had landed only in the legacy repo-root `services/` twin, which production does not run. The deployed `apps/api` copy still called a hardcoded `http://127.0.0.1:8000` loopback that can never reach the service on Render (Render assigns the port via `PORT`), so the fetch always failed and the endpoint silently served the hardcoded Boros Aggro fallback. The repaired `fetch_live_candidates()` (PORT-env base URL, own `/recommendations/decks` payload, card-level deficits from `missing_cards`) is now transplanted into the deployed copy, unchanged in behavior.
- **Why:** production `/collection/stats` reported rares (31,781) exceeding total cards owned (18,308) — an impossible number caused by the print fan-out (118,527 prints / 38,906 cards). And every production next-action answer was the same canned fallback deck instead of a recommendation computed from the player's real missing cards.
- **Verified:** live gate first — production stable (`5e42081f7247`) `/api/health` 200 (database connected, 2 engines) and `/recommendations/decks` returning exactly the 14 decks, three consecutive clean rounds (one transient 500 observed and re-checked clean). Local tests on the Mac worktree, 9/9 pass: the bridge builds its URL from `PORT`, calls `/recommendations/decks`, derives candidates from `missing_cards`, excludes 100%-complete decks, returns a real card from `get_next_action()`, and still falls back when the live call fails; the real stats endpoint assembles its payload against a captured-session double, and its compiled PostgreSQL joins through the canonical-print subquery (`min(card_prints.id)` per `card_id`) with no direct `user_collections`→`card_prints` fan-out join. Full behavioral check of the stats numbers lands when this reaches the dev service / promotion — no local Postgres exists on the Mac.
- **Release state:** dev only (Alpha track). Production (stable/importer-fix) untouched; promotion runs through the Phase 0 PR path (stable → dev, then dev → main) with co-captain review.

## 2026-10-21 — ARENA-4 security fix: JWT secret out of source, into env (PR #18; dev merge e29d4d0)
- **What:** The API signed JWTs with the hardcoded placeholder `"super-secret-key-change-me"` in this public repo (`apps/api/auth.py`), and the token verifier (`apps/api/security.py`) defaulted to the same string. Both now read `SECRET_KEY` from the environment and **refuse to boot** without a real one. A real generated secret is set on both Render services. All previously issued tokens are invalid — users log in fresh.
- **Also fixed:** the register endpoint printed the database bind URL (credentials embedded) to stdout on every signup; the diagnostics/exception prints are removed.
- **Why:** audit AU-1 (Oct 21 code audit). Anyone could have minted a valid token for any account the moment a route trusts these tokens; the log print was leaking live DB credentials into Render logs on every registration.
- **Verified on dev before promotion:** service boots on the env secret (fail-fast guard active in both modules); register/login round-trip passes (201/200). Note: no mounted route verifies JWTs yet (collection/recommendations use stub user ids; matches use an ingest-token header) — wiring `security.get_current_user` in is tracked as audit follow-up AU-1b, before any route relies on auth.
- **Release state:** dev + production (stable/importer-fix) — security fix, promoted same night with owner approval.
