## 2026-10-26 — Slice 5: the Arena Watcher — the desktop app tails Player.log and syncs the deck library (TURBO surge Day 2)

- **What (desktop):** the Arena Watcher. `apps/desktop/watcher.js` tails the MTG Arena `Player.log` (incremental offset reads on a 1.5 s poll — never a whole-file load), and `apps/desktop/watcherParse.js` (pure, shared with the renderer copy) turns lines into state: the deck library from the session dump's `Decks`/`DeckSummaries` plus `EventSetDeckV3` payloads, and the latest `InventoryInfo` snapshot (four wildcard counts, gems, gold, vault progress). The main process syncs that state to the API after sign-in (debounced, fingerprinted so an unchanged log never re-syncs, dirty-flag retry on failure); a new Watcher section in the app shows log path, parse counts, and the last sync summary. Log paths are per-platform (`~/Library/Logs/Wizards Of The Coast/MTGA/Player.log` on macOS, the `AppData\LocalLow` twin on Windows); `ARENA_LOG_PATH` overrides. Robustness is structural: only newline-terminated lines are parsed (Arena writes live), a sentinel prefilter keeps JSON.parse off the match traffic, malformed lines are counted and dropped — never thrown — and a file that shrinks (rotation / new session) resets offset AND parse state so a dead session's decks cannot linger into the next sync. Memory is bounded by the latest state: the full 5.5 MB real log (26,037 lines) parses in ~40 ms at ~9 MB heap.
- **What (engine):** `POST /watcher/sync` + `GET /watcher/decks` (`apps/api/watcher.py`, new `user_decks` / `user_deck_cards` models, `apps/api/schema_slice5_watcher.sql`). Sync mirrors the collection upload's source-of-truth rule at deck scope: each payload deck replaces the stored deck of the same Arena id for the user, and the wildcard counts replace the stored inventory row (so `/collection/stats` reflects the log). Deck rows arrive keyed by Arena grpId; they resolve to engine cards through a new `CardPrint.arena_id` column (Scryfall has always sent it; `seed_cards.py` now stores it). Two findings shaped this: `arena_id` is indexed but deliberately NOT unique — Scryfall's bulk carries prints that share a grpId, and the first seeded attempt at a unique index failed on exactly that — and unresolved grpIds are stored raw and counted unmatched, never dropped or guessed.
- **The honest limit, stated plainly:** the watcher does NOT sync the owned-card collection, because the current client never writes it to the log — a full recursive scan of two real Player.log files (this machine's, Jul 9 + May 31, 2026) found no Cards payload anywhere, and every `InventoryInfo.Changes` in both logs is empty. Deck library + wildcard/currency state is what the log carries, so that is what syncs; the collection stays on the Slice 2 CSV upload, and the app's Watcher section says so in the UI copy. Match ingestion stays out (Sprint 3), as planned.
- **Verified:** on the Mac — fixture logs built from REAL Player.log lines (real decks, real grpIds, real inventory values, one deliberately malformed line, GRE noise): parse yields exactly the 2 real library decks (Killsquad 12 rows / 60 copies; Jeskai Artifacts (4) 20 rows / 61 copies after the dump + EventSetDeckV3 merge; the "?=?"-named precon is skipped, the repo parser's rule), inventory exact (gold 3675, gems 3020, vault 419, wildcards 194/189/9/14); adversarial lines (truncated JSON, a 3 MB non-candidate, a bad EventSetDeck payload) are absorbed and counted, never thrown.
