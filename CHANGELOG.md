# Arena Helper — Changelog

## 2026-10-26 — Slice 5: the Arena Watcher — the desktop app tails Player.log and syncs the deck library (TURBO surge Day 2)

- **What (desktop):** the Arena Watcher. `apps/desktop/watcher.js` tails the MTG Arena `Player.log` (incremental offset reads on a 1.5 s poll — never a whole-file load), and `apps/desktop/watcherParse.js` (pure, shared with the renderer copy) turns lines into state: the deck library from the session dump's `Decks`/`DeckSummaries` plus `EventSetDeckV3` payloads, and the latest `InventoryInfo` snapshot (four wildcard counts, gems, gold, vault progress). The main process syncs that state to the API after sign-in (debounced, fingerprinted so an unchanged log never re-syncs, dirty-flag retry on failure); a new Watcher section in the app shows log path, parse counts, and the last sync summary. Log paths are per-platform (`~/Library/Logs/Wizards Of The Coast/MTGA/Player.log` on macOS, the `AppData\LocalLow` twin on Windows); `ARENA_LOG_PATH` overrides. Robustness is structural: only newline-terminated lines are parsed (Arena writes live), a sentinel prefilter keeps JSON.parse off the match traffic, malformed lines are counted and dropped — never thrown — and a file that shrinks (rotation / new session) resets offset AND parse state so a dead session's decks cannot linger into the next sync. Memory is bounded by the latest state: the full 5.5 MB real log (26,037 lines) parses in ~40 ms at ~9 MB heap.
- **What (engine):** `POST /watcher/sync` + `GET /watcher/decks` (`apps/api/watcher.py`, new `user_decks` / `user_deck_cards` models, `apps/api/schema_slice5_watcher.sql`). Sync mirrors the collection upload's source-of-truth rule at deck scope: each payload deck replaces the stored deck of the same Arena id for the user, and the wildcard counts replace the stored inventory row (so `/collection/stats` reflects the log). Deck rows arrive keyed by Arena grpId; they resolve to engine cards through a new `CardPrint.arena_id` column (Scryfall has always sent it; `seed_cards.py` now stores it). Two findings shaped this: `arena_id` is indexed but deliberately NOT unique — Scryfall's bulk carries prints that share a grpId, and the first seeded attempt at a unique index failed on exactly that — and unresolved grpIds are stored raw and counted unmatched, never dropped or guessed.
- **The honest limit, stated plainly:** the watcher does NOT sync the owned-card collection, because the current client never writes it to the log — a full recursive scan of two real Player.log files (this machine's, Jul 9 + May 31, 2026) found no Cards payload anywhere, and every `InventoryInfo.Changes` in both logs is empty. Deck library + wildcard/currency state is what the log carries, so that is what syncs; the collection stays on the Slice 2 CSV upload, and the app's Watcher section says so in the UI copy. Match ingestion stays out (Sprint 3), as planned.
- **Verified:** on the Mac — fixture logs built from REAL Player.log lines (real decks, real grpIds, real inventory values, one deliberately malformed line, GRE noise): parse yields exactly the 2 real library decks (Killsquad 12 rows / 60 copies; Jeskai Artifacts (4) 20 rows / 61 copies after the dump + EventSetDeckV3 merge; the "?=?"-named precon is skipped, the repo parser's rule), inventory exact (gold 3675, gems 3020, vault 419, wildcards 194/189/9/14); adversarial lines (truncated JSON, a 3 MB non-candidate, a bad EventSetDeck payload) are absorbed and counted, never thrown. Tail legs against a live watched copy: catch-up, an appended inventory landing (gold 3675 → 3925, the real second-session value), a line split across two appends NOT parsed until its newline arrives, and rotation to the second session's file resetting state to exactly that session's deck (Mono-Blue Elementals, 13 rows / 56 copies). Sync round-trip on the local fixture stack: 2 decks / 32 card rows stored, 31 matched, 1 unmatched — grpId 75587 was deliberately left unregistered in the fixture corpus, and it round-trips stored-raw with a null name; `/collection/stats` wildcards move 7/3 → the log's 9/14; a re-sync replaces, never duplicates. Unit checks for the payload shaping pass (`apps/api/test_watcher_sync.py`), and Slice 1–4 regression legs all pass on the new code (auth 401s, upload round-trip + rarity hand-check, Jund acceptance exact — 41 = 10M/25R/5U/1C — and next-action back to Wastewood Verge once the fixture instance carries the bridge's `PORT`). Full-corpus re-seed with `arena_id` stored: 39,000 cards / 119,124 prints (the Slice 3 baseline counts), 19,830 prints carrying an arena_id across 19,808 distinct grpIds (22 prints share a grpId — the duplication that rules out a unique index), and the real logs' grpIds spot-checked home (95195 → Swamp; 90455 → Tinybones, the Pickpocket). Live production smoke ALL PASS incl. the 12,960 baseline gate. Not verified: the GUI window itself (no display session over SSH) and Windows — the watcher's Windows log path and tail behavior especially are standing Slice 6 gate items (workforce1 / Bills-Flexbook).
- **Release state:** dev only (Pre-Alpha). Desktop 0.4.0-alpha.1. Production still serves the pre-Slice-5 engine (no `/watcher` routes, no `arena_id`) until the Phase 0 promotion PRs (#22/#23) merge and `schema_slice5_watcher.sql` + a re-seed run there. Nothing public; the IP-before-public gate and the co-ownership paper still stand.

## 2026-10-26 — Slice 4: recommendations + deck choosing — the wildcard bill is honest (TURBO surge Day 2)

- **What (engine):** (1) **Wildcard pricing fix** (`apps/api/recommendations.py`, `_deck_tally`). The tally priced every deficit at the deck card's HIGHEST-rarity print and counted only rare + mythic wildcards. Both halves contradicted the deck-choosing spec (Step 5: costed at each card's cheapest craftable printing; Step 4: basics free): Fabled Passage has mythic prints but crafts for a RARE wildcard, and uncommon/common deficits were listed but never tallied, understating every bill. Deficits are now priced at the cheapest print (rarity normalized to its wildcard bucket; mythic-tier treatments — special/masterpiece/bonus — price as mythic, an unrecognized rarity as rare rather than 0), tallied in all four buckets, and basic lands count as owned and never cost a wildcard. Both recommendation endpoints serve the full bill; deck detail cards gain `craft_rarity` (the cheapest-print bucket) and a `basic` flag. The display rarity of a deck card is unchanged (highest print, as a deck list shows). (2) **craft_priority fix (KB gap #12)** (`apps/api/craft_priority.py`): the report charged a card's deficit SUMMED across every deck, although one crafted playset serves all decks at once — cost is now the copies to craft ONCE (the largest single-deck deficit), priced off the cheapest print (the print subquery had no ORDER BY and priced an arbitrary print), labeled in its real bucket in all four rarities, and basic lands are excluded (the pre-fix report ranked "craft a Forest" #1 on a collection holding no basics — exposed by the Jund fixture run). The aggregation is extracted as a pure function, `build_craft_priorities`, so it is unit-testable; the ranking formula is unchanged. (3) **Next-action rarity passthrough** (`services/next_action_service.py`): common candidates from `missing_cards` are no longer silently re-labeled rare.
- **What (desktop):** a Recommendations section — the engine's next-action answer (card, cost, deck, the engine's own reasons) with the canned "(Fallback)" answer labeled as the engine's safety default, never dressed up as advice — and deck choosing in the Decks view: the list's Wildcards column is now the full bill total (itemized bill as the cell title), the deck detail header states the bill in words ("41 wildcards — 10 mythic · 25 rare · 5 uncommon · 1 common"), and the card table gains a Craft column priced at the cheapest printing (basics read "free"). Pure logic in `renderer/recommendationsLogic.js`, exercised by the smoke test against the real payloads.
- **Stretch (same day):** the dead `card_synergies` table is wired as seed data (`apps/api/seed_synergies.py`): producer -> payoff pairs derived from the KB §7 oracle-text signal library (lifegain, sacrifice, tokens, spellcast, graveyard, counters, landfall, draw), generated only among cards that appear in a deck in the target database (pool discipline — no corpus-wide cross product), written as labeled seed priors (score 0.6 / confidence 0.5, reason strings say so). Verified on the Jund scratch clone: classifier unit check 10/10, and the seed inserted 6 `graveyard_engine` pairs — the deck's six yard-stocking cards (Bitter Triumph, Collector's Vault, Seize the Spoils, Smuggler's Surprise, and the two surveil lands) into Rakdos Joins Up, its return-from-graveyard payoff — each pair hand-checkable against the card text. The synergy METRIC is untouched; nothing reads the table yet.
- **Acceptance — Matt's Jund Dino numbers, exact:** against a scratch clone of the real card corpus seeded with the Jund Dino Madness list and Billy's collection at the Oct 19 hand-recorded ownership (`apps/desktop/test/jund_fixture.py`), the fixed engine returns **41 wildcards = 10 mythic / 25 rare / 5 uncommon / 1 common**, 71 required / 30 owned / 42.3% complete — the hand-built table to the copy. The four discriminating cards price at their cheapest printings (Fabled Passage RARE, Cavern of Souls RARE, Seize the Spoils COMMON, Bitter Triumph UNCOMMON). Also verified: unit checks 15/15 (`apps/api/test_slice4_wildcard_math.py`, incl. the acceptance case and the craft-once cases); the craft priority report against the same database (Fabled 1 Rare, Cavern 1 Rare, Seize 1 Common, no basics); Slice 1–3 regression legs ALL PASS against the refactored API (fixture Deck A 45.25 / Deck B 42.62 unchanged; upload + rarity hand-checks unchanged); live production smoke ALL PASS incl. the 12,960 baseline gate. Not verified, as before: the GUI window itself (no display session over SSH) and Windows — both remain Alpha-gate items. The synergy METRIC is untouched (still tag density, KB gap #4) — parity-vs-new-metric remains Matt's decision.

## 2026-10-21 — ARENA-4 security fix: JWT secret out of source, into env (PR #18; dev merge e29d4d0)
- **What:** The API signed JWTs with the hardcoded placeholder `"super-secret-key-change-me"` in this public repo (`apps/api/auth.py`), and the token verifier (`apps/api/security.py`) defaulted to the same string. Both now read `SECRET_KEY` from the environment and **refuse to boot** without a real one. A real generated secret is set on both Render services. All previously issued tokens are invalid — users log in fresh.
- **Also fixed:** the register endpoint printed the database bind URL (credentials embedded) to stdout on every signup; the diagnostics/exception prints are removed.
- **Why:** audit AU-1 (Oct 21 code audit). Anyone could have minted a valid token for any account the moment a route trusts these tokens; the log print was leaking live DB credentials into Render logs on every registration.
- **Verified on dev before promotion:** service boots on the env secret (fail-fast guard active in both modules); register/login round-trip passes (201/200). Note: no mounted route verifies JWTs yet (collection/recommendations use stub user ids; matches use an ingest-token header) — wiring `security.get_current_user` in is tracked as audit follow-up AU-1b, before any route relies on auth.
- **Release state:** dev + production (stable/importer-fix) — security fix, promoted same night with owner approval.
